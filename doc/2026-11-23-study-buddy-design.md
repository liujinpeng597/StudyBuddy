# StudyBuddy 个人学习知识工作台设计

> 状态：设计已落实，项目已完成本地实现与验收  
> 日期：2026-11-23  
> 目标版本：个人可用的第一版

## Context

使用者是一名软件工程专业学生，每天按固定主题学习并整理大量 Markdown 笔记，目前在复习 C、C++、Python、数据结构、算法、计算机网络和 Linux。现有笔记内容分散、学习顺序不稳定，复习时难以建立完整的知识网络，也经常出现“看得懂但不会做、不会表达”的问题。

StudyBuddy 不是通用课程平台或刷题网站，而是一套个人学习内容加工与复习工作台。它接收每天的 Markdown 笔记和 LeetCode 解题截图，通过 AI 将内容规范化为知识点，持续合并进一个全局知识网络，并基于当天新增知识与相关旧知识生成测试题。日期只记录内容来源，不作为知识组织边界。模型接入需要在应用内自主配置，默认主模型为 DeepSeek V4.1 Flash。

笔记规范化以本地 `learn-something` 学习笔记方法为内容结构基准：说明定义、作用、相关实现、使用场合、使用原因、优缺点、相关知识点及区别。系统还需要提供全局关键词搜索、知识网络可视化、客观题与问答题，以及 LeetCode 题目的知识关联。

## Goals

- 支持电脑和手机浏览器使用，第一版为响应式 Web 应用，并具备后续封装为 PWA 的基础。
- 在一个导入流程中同时接收每日 `.md` 笔记和 LeetCode 网页截图。
- 将每日问答式笔记拆解为知识点，并按 `learn-something` 的标准结构整理。
- 将新内容自动整合进唯一、持续生长的全局知识网络；重叠概念合并，相关概念建立明确关系。
- 保留原文作为可追溯证据和撤销依据，但主界面只展示整理后的连续知识。
- 通过左侧目录、右侧工作区和知识图完成高效率的检索、阅读与复习。
- 提供覆盖整理后内容和原始笔记的关键词搜索，并在必要时补充语义搜索。
- 根据当天整合内容及相关旧知识生成选择、填空、判断和问答题。
- 将 LeetCode 截图整理为题目档案，并关联知识点、数据结构、算法、复杂度和可优化方向。
- 让每次导入都可追踪、可审查和可撤销，避免 AI 合并逐渐污染长期知识库。
- 允许用户自主接入模型，配置接口地址、模型标识、密钥和任务用途，并在保存前完成连接与能力测试。

## Non-Goals

- 不提供 LeetCode 在线判题、代码运行或自动提交功能。
- 不提供完整课程、视频教学或通用 AI 聊天。
- 不在第一版支持语音面试、实时多人协作或公开分享。
- 不要求用户每天手工审核所有合并结果，也不把每天笔记建成彼此隔离的页面。
- 不实现面向公众的注册、订阅、社区和内容审核体系。
- 不在第一版实现复杂的长期记忆曲线、自动学习计划或多 Agent 自主规划。
- 不把 LeetCode 题解建设成独立刷题产品；题目只服务于知识点复习和面试表达。

## Success Criteria

- 用户能把一天的 6000 字左右 Markdown 和一个或多个截图通过同一次操作导入。
- 导入完成后，相关知识点、关系边、今日变更摘要和可复习内容自动出现，不要求用户复制或手工分类笔记。
- 在基准测试集内，同一知识概念的跨日内容进入同一个节点，而不是生成重复的按日节点。
- 每个知识点能够追溯到一个或多个原始来源片段，并可以撤销某次导入造成的节点和关系修改。
- 搜索能够同时命中知识点标题、整理正文、问答原文、代码和 LeetCode 题干，并跳转到当前知识位置。
- 生成的客观题可以自动判分；问答题能够给出覆盖点、遗漏点、错误点和表达结构反馈。
- 桌面端和手机端均可在一次连续操作中完成“导入、查看整合结果、搜索、答题”的主流程。
- 工作台在 500 个节点规模下仍可流畅完成目录导航、搜索和局部知识图浏览。
- 用户能够通过设置界面接入 DeepSeek V4.1 Flash 或其他兼容模型，无需修改代码或重新部署。
- 模型测试结果能明确区分文本、图片输入和结构化输出能力；密钥保存后不再以明文返回浏览器。

## Recommended Approach

采用 TypeScript 全栈单体 Web 应用，并将耗时导入任务交给同仓库的独立后台 Worker：

- Web：Next.js App Router + React + TypeScript。
- 数据：PostgreSQL + `pgvector`，负责业务数据、版本记录和语义匹配。
- 文件：私有对象存储，保存 Markdown 原文件、截图和提取中间结果。
- 知识图：`@xyflow/react`（React Flow），使用稳定的主题聚类布局。
- AI：服务端 Provider Adapter + 可配置模型档案，默认主模型为 DeepSeek V4.1 Flash，直接调用兼容接口和结构化输出能力。
- 异步任务：导入记录写入 `import_jobs`，Worker 通过 PostgreSQL 任务队列领取并执行。
- 搜索：PostgreSQL 精确/模糊匹配与向量检索混合排序。

第一版不引入 LangChain 或 LangGraph。导入、合并、出题流程固定且可验证，使用自建状态机、严格 Schema 校验和事务提交更简单，也更容易排查长期知识库为何发生变化。AI 只提供提取、判断和内容生成结果，不直接任意操作数据库。

## Alternatives Considered

| 方案 | 优点 | 缺点 | 决定 |
|---|---|---|---|
| Next.js + PostgreSQL + 独立 Worker | 前后端类型统一，部署路径清晰，任务可重试，适合响应式 Web | 需要维护 Web 和 Worker 两个运行进程 | 采用 |
| React + Python FastAPI + PostgreSQL | Python 生态适合文本处理，后端语言对使用者更熟悉 | 前后端需要维护两套模型和部署流程，第一版复杂度更高 | 暂不采用 |
| 本地优先应用 + 云同步 | 离线体验和本机数据掌控最好 | 同步冲突、移动端、知识合并幂等和版本管理显著增加复杂度 | 暂不采用 |
| 使用 LangGraph 编排 AI 流程 | 对复杂分支、断点恢复和多 Agent 协作支持更完整 | 当前流程固定，引入额外抽象和学习成本 | 第一版不采用 |

## Architecture

```text
Browser / PWA
    │
    ▼
Next.js Web Application
  ├─ Workbench UI
  ├─ Search API
  ├─ Review API
  └─ Import API
          │
          ▼
PostgreSQL + pgvector + Object Storage
          │
          ▼
Import Worker
  ├─ Source extraction
  ├─ AI normalization
  ├─ Knowledge resolution
  ├─ Graph mutation proposal
  ├─ Validation and commit
  └─ Question generation
```

Web 应用负责身份校验、输入验证、阅读和交互；Worker 负责耗时任务。数据库是唯一的事实源，对象存储只保存原文件、截图和可重建的附件。知识图的布局坐标属于展示数据，不得成为判断知识关系的唯一依据。

模型接入由独立的 Model Settings Service 管理。第一版支持 OpenAI 兼容的文本接口；模型能力通过显式配置和连接测试确定。默认模型档案展示为 `DeepSeek V4.1 Flash`，实际 Base URL、API Model ID 和凭据由用户在设置中填写，应用不把可能随供应商变化的 Model ID 写死在业务代码中。

### AI 流水线

导入任务按以下状态运行：

```text
queued → parsing → extracting → resolving → committing → completed
                                      └──────────────→ failed
```

1. **解析来源**：验证 Markdown、图片类型和大小，根据任务绑定选择模型，提取图片文本，切分过长文档。
2. **识别问答与知识点**：保留问题语境，识别每个候选知识点及其来源片段。
3. **规范化内容**：按 `learn-something` 结构生成知识点候选。
4. **解析长期节点**：通过标题、别名、模块、精确文本、向量相似度和 AI 判定与已有节点匹配。
5. **生成变更提案**：输出新增节点、更新节点、新增/修改关系、置信度和依据。
6. **确定性校验**：检查 Schema、节点引用、关系方向、重复边、来源覆盖和权限。
7. **事务提交**：在同一事务内写入节点、关系、版本和任务结果。
8. **生成题目**：基于提交后的节点及相邻旧节点生成复习题，并保存来源节点引用。

每次 AI 调用使用结构化输出。单次调用失败可进行一次同类重试；校验连续失败时，任务进入失败状态，不写入半成品。

### 知识合并规则

- 一个知识点是长期节点，具有稳定 ID；学习日期、原文件和原问题通过来源关系附加到节点。
- 标题相同或属于已登记别名时优先复用节点。
- 标题不同但语义高度重合时，AI 输出“合并到哪个节点”的提案，并附上重叠依据。
- 一个概念同时包含基础与进阶内容时，使用同一节点下的结构化小节扩展，不按日期拆成两个主节点。
- 只有确实属于不同概念时才创建新节点，并至少生成一个组成、前置、相似或题目应用关系。
- 关系类型固定为：`prerequisite`、`part_of`、`related`、`contrast`、`applies_to`。
- 不确定的合并仍可完成每日流程，但节点或关系标记为“待复核”，并在后续导入中重新判断。
- 关系不得重复；前置关系提交前检查是否形成明显循环。

### 核心数据模型

| 实体 | 关键字段 | 责任 |
|---|---|---|
| `users` | `id`, `email` | 第一版仅个人账户，数据模型保留用户边界 |
| `source_assets` | `id`, `user_id`, `type`, `storage_path`, `checksum`, `extracted_text`, `study_date` | 保存 Markdown、截图和提取文本 |
| `import_jobs` | `id`, `user_id`, `status`, `progress`, `error_code`, `retry_count`, `started_at`, `finished_at` | 管理异步导入状态 |
| `ai_model_profiles` | `id`, `user_id`, `display_name`, `provider_type`, `base_url`, `model_id`, `api_key_ciphertext`, `capabilities`, `task_roles`, `status`, `last_tested_at` | 保存可自主接入的模型配置与任务绑定 |
| `ai_usage_logs` | `job_id`, `profile_id`, `task_role`, `model_id`, `input_tokens`, `output_tokens`, `latency_ms`, `status`, `error_code` | 记录用量、延迟和失败，不记录密钥或完整敏感正文 |
| `knowledge_nodes` | `id`, `user_id`, `module_id`, `canonical_title`, `summary`, `sections`, `aliases`, `embedding`, `review_status` | 保存全局知识点及整理正文 |
| `knowledge_relations` | `source_id`, `target_id`, `type`, `confidence`, `origin` | 保存有类型的知识关系 |
| `source_node_links` | `source_id`, `node_id`, `source_excerpt`, `question_text` | 追溯知识点与原文 |
| `knowledge_revisions` | `job_id`, `node_id`, `before`, `after`, `change_type` | 支持变更查看和撤销 |
| `leetcode_problems` | `id`, `user_id`, `title`, `number`, `description`, `code`, `complexity`, `optimization_notes` | 保存截图提取后的题目档案 |
| `problem_node_links` | `problem_id`, `node_id`, `relation_type` | 将题目连接到相关知识点 |
| `questions` | `id`, `type`, `prompt`, `answer_key`, `rubric`, `source_node_ids` | 保存生成或人工创建的题目 |
| `attempts` | `question_id`, `answer`, `score`, `feedback`, `created_at` | 保存答题结果和反馈 |
| `graph_layout` | `user_id`, `node_id`, `x`, `y`, `cluster_key` | 保存稳定的展示坐标 |

`knowledge_nodes.sections` 至少包含定义、作用、相关实现、使用场合、使用原因、优点、缺点、相关知识点和区别。正文使用受控 Markdown，表格、代码块和引用需要单独验证。

`ai_model_profiles.task_roles` 至少支持 `image_extraction`、`normalization`、`merge_judgement`、`question_generation` 和 `answer_evaluation`。默认将 DeepSeek V4.1 Flash 用于文本整理、合并判断、出题和问答评估；若该档案不支持图片输入，用户可再配置一个具备视觉能力的档案专门执行 `image_extraction`。

## Interface Design Contract

> 2026-11-23 展示层调整：底层继续保存知识点及其关系，但可视化改为层次化思维导图。左侧工作区以“我的知识”为中心，AI 根据语义建立“领域 → 主题 → 子主题 → 知识点”层级，例如 Linux → 进程管理 → 进程间通信。组和知识点均按由浅入深排序，基础命令与基本概念在前，进阶实现与综合实践在后。关系不在画布中绘制交叉线，只显示关联数量。已有知识可通过“AI 重组分支”重新分类；分类结果按内容签名缓存，重复点击不会随机改变，空分组会被自动清理。

### Experience and Journeys

研究对象是正在形成完整知识体系的软件工程学生。界面的唯一核心任务是让长期积累的知识易于重新找到、理解和输出，而不是展示大量功能卡片。

**每日导入**

1. 用户从顶部“导入”按钮拖入 Markdown 或截图。
2. 界面显示任务阶段、进度和可安全关闭的提示。
3. 完成后默认进入“今日整合”，显示新增节点、更新节点、新关系、待复核项和来源。
4. 用户可在知识图中看到“今日织入”高亮，并直接开始答题。

**知识浏览**

1. 左侧目录按“模块 → 主题 → 知识点”展示完整知识树。
2. 今日有变化的节点带有低对比度强调，不改变原树结构。
3. 点击知识点后，右侧打开知识正文；相关题目、来源和局部关系在相邻标签或侧栏出现。

**搜索**

1. 用户直接在左侧固定搜索框、桌面顶部搜索框或手机常驻搜索框输入，不打开搜索弹窗；`Ctrl/Cmd + K` 聚焦桌面顶部搜索框。
2. 输入框下方动态展示匹配结果，包含模块路径、命中片段和内容类型。
3. 结果支持键盘上下选择、回车打开和 Esc 关闭。
4. 点击结果后进入对应的当前知识节点。

**复习**

1. 用户从“测试”标签进入当天复习。
2. 系统先生成客观题，再提供问答题。
3. 客观题立即判分；问答题显示覆盖点、遗漏、错误和表达结构反馈。
4. 所有题目显示来源知识点，用户可以跳回相应内容。

**恢复**

导入失败不清除已保存来源；提交失败不影响已有网络。用户可从导入记录查看变更摘要并撤销本次合并。

**自主接入模型**

1. 用户点击顶部栏用户头像左侧的齿轮“总设置”，从弹出菜单进入“模型设置”或“显示与展开”。
2. 用户填写显示名称、接口地址、API Model ID 和 API Key，并为文本或图片任务选择用途。
3. 保存前执行连接测试：验证鉴权、文本响应、JSON 结构化输出；用户启用图片能力时再执行一次小型图片输入测试。
4. 系统显示可用、部分可用或失败结果；只有通过必要角色的测试后，档案才能成为该任务默认模型。
5. 密钥仅可替换或清除，不再返回完整明文；默认档案预置名称 `DeepSeek V4.1 Flash`，但实际接口参数由用户保存。

“显示与展开”是总设置的独立子页面，分别保存左侧知识目录和知识思维导图的默认展开/折叠状态。设置按用户保存并跨设备同步；用户仍可在当前页面临时手动展开或折叠任意模块。用户头像菜单只保留账户数据和退出登录。

### Layout and Responsive Behavior

桌面端工作台：

```text
┌──────────────────────────────────────────────────────────────┐
│ 品牌/搜索                导入       任务状态       账户      │
├──────────────┬───────────────────────────────────────────────┤
│ 知识树       │ 今日整合 │ 知识图 │ 测试 │ 导入记录          │
│              │                                               │
│ C++          │ 当前工作区                                    │
│  类与对象    │                                               │
│   构造函数   │ 正文、局部知识图、来源或题目                  │
│   虚函数     │                                               │
│ 网络         │                                               │
│ LeetCode     │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- `>= 1280px`：左侧目录约 280px，右侧工作区自适应；知识图可与正文分栏。
- `768px～1279px`：目录缩窄到约 240px，可折叠；知识图默认全宽。
- `< 768px`：目录变为抽屉；顶部保留搜索和导入；工作区标签横向滚动；知识图与正文使用页面切换。
- 导入进行时允许用户继续浏览已有知识，不锁定整个工作台。

### Visual System

视觉方向为“清新、克制的技术学习台”。灵感来自纸张、工程笔记和依赖关系图，不采用紫色渐变、发光边框、玻璃拟态或大面积装饰性动画。知识网络是唯一具有明显视觉张力的区域，其余界面保持安静。

标志性元素为知识图上的“今日织入”：当天新增节点以青绿色细描边出现，新关系在首次查看时沿路径短暂点亮，随后恢复静态；知识图旧区域始终弱化，确保用户能看懂今天为网络补上了什么。

| Token | 值 | 用途 |
|---|---|---|
| `surface` | `#F7F8F5` | 主背景，暖白偏浅灰 |
| `surface-raised` | `#FFFFFF` | 阅读区、弹层和选中内容 |
| `ink` | `#1F2A26` | 主文字 |
| `accent` | `#2F7D6A` | 当前节点、主动作、新增关系 |
| `attention` | `#B8792E` | 待复习、待复核和进度提醒 |
| `danger` | `#B24B3F` | 错误和破坏性操作 |
| `border` | `#D7DED9` | 分隔线、节点边界和输入框 |

- 字体：中文正文使用系统无衬线字体或 Noto Sans SC；代码、时间、复杂度元数据使用等宽字体。
- 类型层级：页面标题 28/36，区块标题 20/28，正文 15/26，辅助文字 13/20，代码 13/22。
- 间距使用 4px 基础网格；主要区块间距 24px；正文行宽控制在适合中文阅读的范围。
- 圆角以 8px 和 12px 为主；边框 1px；仅弹层和浮层使用轻阴影。
- 动效时长 120～180ms，只用于任务状态、节点选中和今日关系出现；支持减少动态效果。

### Components, Content, and States

| 组件 | 内容与行为 | 必需状态 |
|---|---|---|
| 全局搜索 | 输入关键词、筛选、结果列表、命中高亮 | 默认、聚焦、加载、无结果、错误、移动端全屏 |
| 知识树 | 模块与节点层级、展开折叠、今日变化标记 | 空、加载、选中、展开、错误 |
| 导入面板 | Markdown/截图拖放、文件列表、提交 | 空闲、拖入、校验中、上传中、失败 |
| 任务进度 | 当前阶段、百分比或阶段提示、关闭后继续 | 排队、解析、整理、提交、完成、失败 |
| 今日整合 | 新增/更新节点、关系、待复核项、来源 | 首次导入、无变化、部分失败、完成 |
| 知识阅读区 | 规范化正文、目录、来源引用、代码块 | 默认、加载、空节点、局部错误 |
| 知识图 | 节点、关系类型、缩放、聚焦、今日织入 | 全局、局部、选中、搜索定位、空图、大型图提示 |
| 客观题 | 单选、多选、填空、判断、即时判分 | 未答、已选、正确、错误、解析 |
| 问答题 | 文本作答、提交、AI 反馈 | 未答、提交中、已评分、无法评分、重试 |
| LeetCode 档案 | 原截图、题号、题干、代码、知识点和优化标记 | 字段完整、缺少题号、AI 推断、无关联 |
| 模型设置 | 模型档案、接口地址、Model ID、写入式密钥、能力测试、任务绑定 | 未配置、测试中、可用、部分可用、失败、已停用 |
| 导入记录 | 时间、来源、状态、变更摘要、撤销 | 成功、失败、已撤销、撤销中 |

界面术语使用“知识点、模块、关系、今日整合、测试、导入记录”，避免直接向用户暴露 embedding、job、node 等实现术语。错误信息必须说明发生了什么、已有数据是否安全以及可执行的下一步。

### Accessibility and Visual Verification

- 所有主要操作可仅用键盘完成；知识树支持方向键和回车。
- 焦点样式必须清晰，不能只依赖颜色区分关系和状态。
- 正文、强调色文字和背景达到 WCAG AA 对比度。
- 知识图必须提供等价的目录/列表视图，屏幕阅读器不依赖 Canvas 关系线。
- 触控目标不小于 44×44px，手机端搜索和导入始终可访问。
- 尊重 `prefers-reduced-motion`，关闭“今日关系”路径动画。
- 视觉验收覆盖 1440×900、1024×768、390×844 三个视口。
- 必须截图验证今日整合、搜索结果、知识图选中、客观题反馈和问答题反馈。

| AI Adapter | 按任务解引用模型档案，统一文本/图片调用、结构化生成和重试 | Model Settings Service、外部模型 API | 返回结果必须校验；不得绕开任务绑定 |

## Data Flow

### 导入与合并

1. Web 校验文件名、MIME、大小并计算校验和。
2. 原文件写入私有对象存储，`source_assets` 和 `import_jobs` 写入数据库。
3. Worker 领取任务，提取 Markdown 结构或截图中可见内容。
4. AI Adapter 生成知识点候选、规范化内容和关系候选。
5. Knowledge Service 使用别名、文本、向量和 AI 判定解析已有节点。
6. 校验器拒绝非法关系、无来源节点和重复结构。
7. 单事务提交节点、关系、来源链接、版本记录和题目。
8. Web 轮询或订阅任务状态并展示整合结果。

### 搜索

1. 查询被规范化为关键词、模块筛选和内容类型筛选。
2. 服务端执行标题/别名/正文/来源的精确和模糊匹配。
3. 同时执行向量相似度检索，合并重复结果。
4. 排序优先考虑精确命中、标题命中、最近访问和更新时间。
5. 返回原文命中上下文及对应的当前知识节点。

### 测试与反馈

1. Review Service 选择今日更新节点及其一跳相关旧节点。
2. 根据题型模板生成题目、标准要点和评分 rubric。
3. 客观题按标准答案判分；问答题由 AI 按 rubric 返回结构化反馈。
4. 每次答题保存题目版本和反馈，不自动覆盖知识点。

### 撤销

1. 导入记录打开对应 `knowledge_revisions`。
2. 系统检查被撤销节点是否还被后续导入引用。
3. 无冲突时恢复导入前状态；有冲突时列出后续引用并要求保留或合并。
4. 撤销本身记录为新版本，不物理删除历史。

### 模型接入与调用

1. 用户在模型设置中填写接口地址、Model ID 和 API Key。
2. Model Settings Service 验证 URL 格式，在服务端解密或加密凭据，并执行最小化连接测试。
3. 文本测试确认模型可返回符合结构化 Schema 的 JSON；图片测试仅在用户声明需要图片能力时执行。
4. 测试通过后保存能力标记和任务绑定，例如默认主模型使用 DeepSeek V4.1 Flash，图片提取可绑定同一档案或单独视觉档案。
5. Worker 开始任务时按 `task_role` 解析模型档案，由 AI Adapter 发起调用并写入 `ai_usage_logs`。
6. 模型失败不会自动切换未授权模型；只有用户显式配置备用档案时才允许按顺序回退。

## Error Handling

| 失败场景 | 系统行为 |
|---|---|
| Markdown 过大或格式异常 | 保留原文件，说明问题；允许重新上传或调整后重试 |
| 图片不是支持的格式 | 在提交前拒绝，不创建任务 |
| 截图中缺少题号或题干 | 保存可提取字段并标记“信息不完整”，不猜测缺失原文 |
| AI 超时或限流 | 指数退避重试；超过限额后任务失败并允许手动重试 |
| AI 返回不符合 Schema | 进行受控修复调用；仍失败则停止提交 |
| 模型接口不可访问或密钥无效 | 将档案标记为不可用，展示 HTTP 状态与可执行检查项；已有知识不受影响 |
| 主模型不支持图片输入 | 若未配置视觉档案，阻止截图提取并提示配置；Markdown 文本整理仍可继续 |
| 模型测试只通过部分能力 | 保存档案但不自动绑定未通过的 `task_role` |
| 模型接口返回不兼容格式 | 记录脱敏后的响应结构摘要，停止该任务，不在数据结构中静默猜测 |
| 文档过长超过上下文限制 | 按问题和章节切片，生成中间摘要后再合并 |
| 合并置信度低 | 完成可确定部分，把冲突标记为“待复核” |
| 数据库提交失败 | 整体回滚，不产生半更新知识网络 |
| 搜索结果为空 | 展示无结果状态和可移除的筛选条件 |
| 问答题反馈失败 | 保留用户答案，显示重试，不伪造评分 |
| 撤销存在后续依赖 | 展示依赖关系，阻止直接破坏性撤销 |

## Security

- 第一版只开放个人账户；优先使用邮箱魔法链接或受控登录方式。
- 所有业务表带 `user_id`，数据库启用行级访问控制；Worker 使用最小权限服务凭据。
- 原文件和截图存入私有 Bucket，通过短期签名 URL 访问，不生成永久公开地址。
- 系统加密主密钥、对象存储密钥和数据库服务密钥只存在于服务端环境变量，禁止进入浏览器包。
- 用户在设置中填写的模型 API Key 使用服务端主密钥进行 AES-256-GCM 加密后保存；数据库只存密文，界面只显示掩码尾号。
- 支持加密主密钥轮换：新版本主密钥启用后逐步重加密模型凭据，旧主密钥只在迁移窗口内保留。
- 模型设置 API 不返回完整密钥；日志、错误追踪和用量记录必须过滤 Authorization 头及密钥原文。
- 自定义模型 Base URL 只接受 HTTPS；如未来明确支持本机模型，通过单独开关允许受控的 localhost 地址，防止普通配置形成服务端请求伪造入口。
- Markdown 渲染禁用原始 HTML 和脚本；代码块按纯文本高亮，避免 XSS。
- 笔记内容视为不可信数据，不能把其中的语句当作系统指令；AI 提示词明确隔离数据与规则。
- 上传文件验证扩展名、MIME、大小和解码结果；不执行上传内容。
- 对导入、搜索、问答题评分实施每日 AI 用量上限和速率限制，避免意外费用。
- 调用外部模型前在设置页明确提示截图和笔记内容会发送给所配置的服务商；用户可随时清除密钥和停用档案。
- 提供完整数据导出和删除能力；删除时同步处理数据库记录、向量和私有文件。
- 保存导入版本和变更审计，任何自动合并都可定位到来源、模型和任务。

## Boundaries and Dependencies

| 边界 | 拥有 | 不拥有 |
|---|---|---|
| Web UI | 布局、交互、输入、展示 | 知识合并规则、AI 密钥 |
| Import Worker | 导入状态机、切片、调用 AI、提交任务结果 | 用户界面状态 |
| Knowledge Service | 节点、关系、别名、版本和合并校验 | 文件解析、图形布局 |
| Model Settings Service | 模型档案、能力检测、任务绑定和密钥加密 | 知识内容和最终任务结果 |
| AI Adapter | 模型调用、结构化输出、重试和用量记录 | 模型密钥明文、最终知识事实和数据库权限 |
| Search Service | 索引查询、结果合并和排序 | 知识节点写入 |
| Graph Presenter | 坐标、缩放、过滤和高亮 | 关系真实性判断 |
| Source Vault | 原文件、截图和附件 | 可搜索的最终知识正文 |

外部依赖包括用户配置的模型服务、托管 PostgreSQL、对象存储和 Web/Worker 部署平台。DeepSeek V4.1 Flash 是默认主模型，但任务角色通过模型档案解析，因此更换 Base URL、Model ID 或供应商时不得改变领域数据模型。AI 输出具有不确定性，所有写入必须通过本地 Schema 与业务规则校验。

## Testing

### 单元测试

- Markdown 文件校验、问答拆分和超长文档切片。
- `learn-something` 输出 Schema 校验与缺失章节处理。
- 节点别名匹配、重复关系检测、前置关系循环检测和版本差异。
- 关键词、模糊和向量搜索的结果合并。
- 客观题答案标准化与计分。
- 模型档案字段校验、能力任务绑定、密钥加密轮换与掩码输出。

### 集成测试

- 使用真实的 PostgreSQL 和对象存储运行导入任务。
- 验证 Worker 任务领取的幂等性、重试和失败回滚。
- 使用固定 AI 响应测试“类基础 → 类进阶”合并为同一知识主题。
- 验证 Q&A 原文命中后能跳转到合并后的知识点。
- 验证 LeetCode 截图提取和知识点关联。
- 验证撤销只移除指定导入的影响，不删除后续有效内容。
- 验证 DeepSeek V4.1 Flash 文本连接测试、结构化输出测试和可选图片能力测试。
- 验证文本主模型不支持图片时会阻止截图提取，而不会发送无效请求或静默丢弃截图。

### AI 评测

建立一组固定基准资料，至少包含：

- C++ 类基础与类进阶的两天问答笔记。
- 虚函数、多态、虚表和相关概念辨析。
- 计算机网络分层、TCP 拥塞控制等问答。
- 数据结构与算法中相近概念的比较。
- 含多个知识点的 6000 字综合笔记。
- 只有题目描述和代码的 LeetCode 解题截图。

评测关注结构化字段完整性、概念去重、关系合理性、事实一致性、题目是否基于来源以及问答题反馈是否指出真实遗漏。不得只比较生成文本是否逐字相同。

### 端到端测试

- 从导入到今日整合完成的完整主流程。
- 导入后通过搜索找到旧知识点并打开知识图。
- 完成客观题和问答题并查看反馈。
- 撤销导入后确认知识树、搜索和知识图同步恢复。
- 桌面、平板和手机三种视口的关键交互。

### 性能与可靠性

- 测试 500 个节点、1500 条关系的目录和知识图交互。
- 上传与 AI 处理期间刷新页面，任务仍能恢复显示。
- AI 超时、限流、部分成功和重复提交不会造成重复节点或重复关系。
- 模型档案不可用时任务停留在可重试状态，已有知识、导入来源和聊天外数据不被破坏。
- 生产任务记录耗时、模型调用量、失败阶段和重试次数。

## Rollout

1. 先建立本地开发环境、数据库迁移和对象存储。
2. 用少量历史笔记验证规范化模板、节点合并和搜索。
3. 导入一周真实资料，检查知识树、知识图和撤销是否符合实际复习方式。
4. 验证桌面和手机主流程后，再开放持续每日导入。
5. 生产环境启用每日数据库备份和对象存储备份。
6. 新模型或新提示词先在固定基准资料上评测，再切换生产配置。
7. 失败的任务保留原文件和可重试状态，不自动清理。
8. 初次接入 DeepSeek V4.1 Flash 时先完成连接和能力测试，再用一组历史笔记验证结构化输出质量。

第一版没有既有生产数据需要迁移。若后续调整知识 Schema，使用增量迁移和版本化重处理，不覆盖原始资料。

## Deferred Questions

- **截图视觉能力**：默认文本主模型为 DeepSeek V4.1 Flash；若所接入接口不支持图片，则需要另配视觉模型或 OCR 档案。实现时必须通过图片能力测试，不能根据模型名称假定支持。
- **模型费用与备用策略**：第一版记录每项任务用量并允许设置用户明确的备用模型；未配置备用时不自动产生额外供应商费用。
- **托管平台**：默认使用托管 PostgreSQL 与对象存储，Web 可在支持 Node.js 的平台部署，Worker 可在独立常驻服务部署；实现时按网络可达性确定具体供应商。
- **知识图大规模布局**：第一版采用稳定主题聚类并保存坐标；当节点超过 800 个时再评估分层折叠或按需加载。
- **间隔复习算法**：第一版以当天整合和相关旧知识生成题目，不实现完整记忆曲线；后续根据答题记录增加复习优先级。
- **暗色主题**：第一版只提供已批准的浅色主题；后续在保持同一设计令牌角色的前提下增加。
- **语音面试**：后续版本增加转写和表达反馈，不进入第一版范围。
- **多用户公开服务**：数据模型保留 `user_id`，但第一版不实现注册、分享、团队或公开知识库。
