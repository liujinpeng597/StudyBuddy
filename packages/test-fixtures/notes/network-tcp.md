# TCP 拥塞控制

## 问题：TCP 为什么需要拥塞控制？

发送方即使知道接收方还有缓存空间，也不能无限增加发送速率。中间网络链路的容量和路由器队列有限，过多流量会造成排队延迟、丢包和吞吐下降。拥塞控制根据网络反馈调整发送速率，尽量提高利用率并保持公平。

## 问题：慢启动和拥塞避免的区别是什么？

慢启动阶段拥塞窗口从较小值开始，每收到一个确认便增加窗口，通常按往返时间指数增长。达到慢启动阈值后进入拥塞避免，窗口增长速度降为近似线性，以更谨慎的方式探测可用带宽。

## 问题：发生丢包后会怎样调整？

不同 TCP 拥塞控制算法会采用不同策略。常见机制包括减小拥塞窗口、重新设置慢启动阈值、使用快速重传与快速恢复，以及根据重复确认或显式拥塞通知区分轻微拥塞和严重拥塞。

## 相近概念：流量控制与拥塞控制

流量控制关注接收方能否及时处理数据，通过接收窗口限制发送方可发送但尚未确认的数据。拥塞控制关注中间网络能否承载流量，通过拥塞窗口和网络反馈调整发送速率。实际发送窗口受两者共同约束。
